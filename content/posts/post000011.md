# 二 学到的知识
## (1) 有关```allocator```本身
```allocator```就是古```C++```掌管任何容器的神，离了它谁也跑不起来，因为它是负责分配内存的模板类。  
其设计思想为分配内存和填入数据分离，分别由两套相对的基本功能实现。
基本功能就四个，之前写```vector```的时候我也见识过了：```allocate```，```deallocate```，```construct```和```destroy```。  
一套是```allocate```和```deallocate```，一个负责分配内存，一个负责回收内存。
另一套是```construct```和```destroy```，一个负责填入数据，一个负责清除数据。
写起来仍然要借助一些底层库，不过借助的都是一些像```malloc```之类的不得不用的方法。
## (2) 四个方法的实现
这四个方法都是建立的那一方难，摧毁的那一方简单。果然这个世界是熵增的吗。（不过如果说内存重置为0，也算是熵减。。又在发癫了）  
```allocate```需要```malloc```一块内存，成功返回内存，失败返回```std::bad_alloc()```。  
```deallocate```直接```free```掉，把内存上交堆管理器就行。  
```construct```尤其雷霆，我直接把代码贴在这里，下面的标题会仔细讲解：  
```cpp
template <typename... Args>
void construct(T* p, Args&&... args)
{
    ::new ((void*)p) T(std::forward<Args>(args)...);
}
```
简单来说就是使用```placement new```，在申请的内存上调用了构造函数。  
```destroy```也是很简单，直接调用析构。  
## (3)从```construct```学到的诸多内容
### <1> 参数包
最直击我灵魂的是这个玩意，参数包。  
我是真的第一次听说```C++```还能有这种这么nb的东西。  
简单来说，参数包就是把一坨各种类型的参数打了个包，需要的时候再拆包取用。  
对于我们的```construct```代码，大致是这样的：在```template <typename... Args>```一行中，用泛型声明了Args是一个泛型的参数包类型，同时```...```指定了声明的是参数包类型而不是普通类型。  
在下面的参数列表中，```Args&&... args```则表示传参进来一个转发引用（别急，下面会讲转发引用）的```args```参数包，```...```仍然表示声明。  
在方法内部的```...```则表示拆包，将数据取用，填入构造函数。  
### <2> ```placement new```语法
```placement new```这个东西，我之前在写```vector```听大肥鱼提到过，但是没深究，终于还是来折磨我了。  
它的语法格式为：new （地址） 类型（参数），意为在地址处调用类型的构造函数。
而在我们的代码中，```::new```这里的```::```表示使用全局的```new```运算符，避免因重载而产生歧义。  
```((void*)p)```中，使用(void*)强转类型是安全的，因为任何指针都可以转为(void*)，而转换的目的是对齐颗粒度，因为```placement new```强制要求地址为(void*)类型。  
然后这一行一大坨代码直接给我吓哭了。连夜逃离```C++```。不开玩笑的说今年这行代码将是最震撼我的一行。

### <3> ```完美转发```
这个算是很抽象的一个概念，我也没搞太明白，我就按着我的理解说说。  
首先是```construct```参数列表里的```Args&&... args```。这个```&&```不是我上次写后端的移动语义，它是一个转发引用，与下面的```std::forward```搭配使用。  
那么怎么区分```&&```到底是完美转发还是移动语义呢？大肥鱼跟我说要看有没有发生类型推导，发生了类型推导（一般只在泛型会发生类型推导罢）就是完美转发，否则是普通的移动语义。  
而```std::forward```和```T&&```两个东西又有很大的区别。我又问了大肥鱼，```T&&```是真正发挥类型推导作用的，放在参数列表里的，开启完美转发开关的占位符，而```std::forward```则是在函数体内部调用，强制转换实参类型的一个方法。  
说了这么多形式的内容，该说说完美转发究竟是什么东西了。  
```C++```最注重的就是性能，而性能是一点点抠出来的，我们的```allocator```当然不能落后在起跑线上，即使是```construct```这种地方也要时刻小心多余的开销——例如拷贝。  
而```C++```拥有左值、右值两种值，其中左值是需要拷贝的，右值相当于常量无需拷贝，如果在```construct```时，```placement new```那里直接填写```T(args...)```，即使调用时填写了右值，也要再次进行拷贝，开销完全无法控制，因此完美转发可以保留左值和右值属性，直接避免了更大的开销，太美妙了。  
所以我们用```T&&```声明了这里的值需要完美拷贝，而```std::forward```相当于一个类型转换器，因为```args```作为具名变量属于左值，直接往构造函数里塞会挨个拷贝，出现上面提到的开销大的问题，所以使用```std::forward```转换了类型，把该右值的转换为右值，降低开销。  
我的天哪。理解了这个玩意简直是大脑升级。
